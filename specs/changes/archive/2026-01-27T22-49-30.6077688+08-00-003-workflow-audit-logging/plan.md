# Implementation Plan: Workflow audit logging for scripts

**Branch**: `003-workflow-audit-logging` | **Date**: 2026-01-27 | **Spec**: spec.md
**Input**: Feature specification from `specs/changes/003-workflow-audit-logging/spec.md`

## Summary

This plan implements workflow audit entries for state-changing scripts using a shared PowerShell logging helper that appends JSONL records to
`specs/logs/workflow-audit.jsonl`. It delivers append-only, sanitized audit history for compliance reviews and failure troubleshooting.

## Architecture Overview

### System Components

```
[Workflow script]
  |
  v
[Write-WorkflowAuditEntry]
  |
  v
specs/logs/workflow-audit.jsonl
```

#### Decision 1: Centralize audit logging in shared helper

- **Choice**: Add a `Write-WorkflowAuditEntry` helper in `specs/scripts/common.ps1` used by all state-changing scripts.
- **Rationale**: Ensures consistent schema, sanitization, and error handling across every workflow action.
- **Alternatives Rejected**: Inline logging per script, which risks schema drift and missing fields.
- **Tradeoffs**: Adds a shared dependency but reduces duplication and improves governance compliance.

#### Decision 2: JSONL append-only audit file

- **Choice**: Store audit entries as JSONL lines in `specs/logs/workflow-audit.jsonl` and append using .NET `AppendAllText` with retry/backoff safeguards.
- **Rationale**: Matches the constitution requirement and keeps audit history immutable and tool-friendly.
- **Alternatives Rejected**: CSV or a structured database; both add parsing constraints or new dependencies.
- **Tradeoffs**: Requires disciplined schema evolution but preserves minimal dependency footprint.

### Integration Points

| System | Direction | Contract | Notes |
|--------|-----------|----------|-------|
| File system audit log | Writes | `contracts/workflow-audit/create.yaml` | Appends JSONL entries; creates directory if missing. |
| Audit log readers | Reads | `contracts/workflow-audit/list.yaml` | Consumers read entries for review and compliance. |
